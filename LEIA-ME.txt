LINKART QR — VERSÃO ADAPTADA PARA GITHUB PAGES

1) Publicar no GitHub
- Crie ou abra o repositório onde pretende alojar a aplicação.
- Carregue os ficheiros desta pasta directamente na raiz do repositório (index.html, firestore.rules e este LEIA-ME.txt).
- No GitHub, abra Settings > Pages.
- Em Build and deployment, escolha Deploy from a branch.
- Seleccione a branch (normalmente main) e a pasta /(root), depois clique Save.
- Aguarde a publicação. O endereço será semelhante a https://UTILIZADOR.github.io/NOME-DO-REPOSITORIO/

2) Como funcionam os QR Codes
- Esta versão usa rotas com fragmento: https://UTILIZADOR.github.io/NOME-DO-REPOSITORIO/#/c/IDENTIFICADOR.
- Este formato é compatível com GitHub Pages e não necessita de _redirects nem de ficheiro 404.
- Na aplicação, em Endereço do site (opcional), deixe o campo vazio para usar automaticamente o endereço actual.
- Se preencher esse campo, indique a URL base completa do GitHub Pages, incluindo o nome do repositório e sem # no fim. Ex.: https://UTILIZADOR.github.io/NOME-DO-REPOSITORIO

3) Firebase — atenção antes de usar
- O index.html já contém uma configuração Firebase existente (projectId: proverbial-anagram-wdtd0). Não crie outro projecto sem substituir também a configuração no index.html.
- A aplicação utiliza a base de dados Firestore com o identificador: ai-studio-linkartqrmanager-bf986154-10ce-4dec-b45b-654bd3d574c0. Confirme que essa base de dados existe no projecto Firebase configurado.
- Em Firebase Console > Authentication > Settings > Authorized domains, adicione o domínio do GitHub Pages: UTILIZADOR.github.io (sem https:// e sem caminho do repositório).
- Confirme que o método de autenticação Google está activado.
- Publique o conteúdo de firestore.rules na base de dados Firestore utilizada pela aplicação.

4) Logótipos e limite do Firestore
- A aplicação aceita apenas PNG, JPG e WEBP para logótipos.
- O limite do ficheiro seleccionado é 700 KB. Imagens maiores são rejeitadas; não há redução nem compressão automática.
- O logótipo é guardado no próprio documento Firestore como imagem Base64, mantendo os bytes originais do ficheiro.
- Antes de guardar, a aplicação verifica o tamanho UTF-8 do documento e bloqueia gravações acima de 1.000.000 bytes para manter uma margem abaixo do limite máximo de 1 MiB do Firestore.
- Como a codificação Base64 aumenta o tamanho, 700 KB é um limite prático, não uma garantia para cartões com muitos outros dados. Se o documento ultrapassar o limite seguro, será necessário usar um logótipo menor ou encurtar os restantes campos.

- O ficheiro firestore.rules contém as regras de segurança fornecidas para o LINKART QR.
- A leitura individual de cartões é pública para qualquer ID válido; a listagem e as operações de escrita exigem o administrador verificado.

6) Novas funcionalidades: TikTok e localização
- O formulário de criação/edição de cartões inclui TikTok (nome de utilizador ou link) e Localização (morada ou nome do local).
- Quando existe TikTok, é apresentado como contacto clicável na página pública do cartão.
- Quando existe localização, é apresentado um mapa incorporado abaixo dos contactos, com ligação para abrir o local no Google Maps.
- A localização usa o campo "address", já contemplado nas regras Firestore fornecidas.
- O mapa depende de ligação à internet e dos serviços de mapas da Google; não é necessário activar Firebase Storage nem o plano Blaze.

8) Mapa do local exacto a partir de links do Google Maps
- No campo Localização pode colar: um link curto (maps.app.goo.gl/…), um link completo do Google Maps, coordenadas (ex.: -25.9692, 32.5732) ou uma morada em texto.
- Ao clicar em "Verificar localização" ou "Guardar cartão", a aplicação identifica o destino real do link e guarda no próprio documento do cartão: mapLat, mapLng e mapLabel. A página pública usa essas coordenadas e mostra o mapa do local exacto (sem pedir nada a serviços externos para o resolver).
- O campo "address" continua a guardar o que foi colado (máx. 200 caracteres; se o link completo for maior, é substituído pelo nome/coordenadas).
- Links curtos: o navegador não consegue ler o destino de um link curto directamente (bloqueio CORS do Google). Por isso a aplicação usa serviços públicos de redirecionamento como alternativa (allorigins.win e corsproxy.io). Para maior fiabilidade, publique o resolvedor gratuito resolver-cloudflare-worker.js no Cloudflare Workers e coloque o seu endereço em MAP_RESOLVER no início do bloco de mapa do index.html.
- Se o link curto não puder ser resolvido, o cartão pode ser guardado na mesma: ao abrir, tenta resolver novamente e, se falhar, mostra o botão "Abrir no Google Maps". A forma garantida é colar o link completo (aberto no navegador) ou as coordenadas.
- Cartões antigos com link no campo Localização passam a mostrar o mapa ao abrir (se a resolução funcionar); volte a guardá-los para gravar as coordenadas de forma definitiva.
- Publique de novo o firestore.rules: foram acrescentadas validações opcionais para mapLat, mapLng e mapLabel. Firestore, limite de 700 KB dos logótipos, TikTok, QR, exportações e restantes funcionalidades ficam inalterados.


7) Tamanho padrão e PDF A4
- Novos cartões são criados por defeito com 8,5 × 5,4 cm, na horizontal. Os cartões já guardados mantêm o tamanho que têm; basta mudar em "Tamanho do cartão" e guardar.
- O botão "Baixar PDF (A4)" gera uma página A4 vertical com a frente e o verso lado a lado, à escala real, com margem de 1,5 cm em cima, 0,6 cm entre a frente e o verso e contorno cinzento tracejado fino para facilitar o corte.
- Se o cartão for demasiado grande para caber em A4 (lado a lado, ou um sobre o outro), o PDF usa uma página à medida do conteúdo.


8) Modelos de cores
- No editor do cartão, "Modelo de cores" permite escolher entre Clássico (por defeito, o que já existia), Preto e laranja, Branco e azul-marinho, Azul-marinho e Preto e verde-limão.
- O modelo aplica-se à frente e ao verso, à pré-visualização, ao PNG, ao JPG e ao PDF, e também às cores do cabeçalho e dos botões da página pública.
- O logotipo mantém sempre a cor original. Nos modelos escuros a frente tem fundo branco, com as faixas coloridas nos cantos, e o verso mantém o fundo escuro, com o logotipo sobre um painel branco.
- O QR code fica sempre preto sobre painel branco, para continuar legível.
- Os cartões antigos, sem modelo guardado, continuam Clássicos.
- IMPORTANTE: publique de novo o conteúdo de firestore.rules no Firebase (inclui os campo tema).
